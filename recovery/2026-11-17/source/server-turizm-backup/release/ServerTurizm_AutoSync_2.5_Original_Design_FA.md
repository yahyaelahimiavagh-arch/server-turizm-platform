# Server Turizm Auto Sync 2.5 — فقط داده، همان طراحی اصلی

## چه چیزی اصلاح شد؟

نسخهٔ قبلی 2.4 در حالت `Public display = ON` شورت‌کد `[stppi_umre_programs]` و برخی مسیرهای برنامه/هتل را با کارت‌های سادهٔ Sync جایگزین می‌کرد. نسخهٔ 2.5 **این جایگزینی را به‌طور کامل حذف کرده است**. از این پس تنها افزونهٔ اصلی **Program Publishing Integration (STPPI)** کارت‌ها، گالری، تاریخ، قیمت، جزئیات، CSS و لینک‌های عمومی را نمایش می‌دهد. قالب و HTML و CSS قبلی تغییر نکرده است.

- فایل Apps Script فعلی را تغییر ندهید؛ تریگرهای قدیمی را دوباره نصب نکنید.
- افزونه‌های Direct Sync Foundation، Program Intelligence، Program Publishing Integration، Hotel Intelligence و Program Foundation را فعال نگه دارید.
- Auto Sync همچنان داده‌های برنامه و هتل را از Google Sheets به موجودیت‌های WordPress می‌فرستد.
- پس از تکمیل موفق همگام‌سازی، برنامه‌های **جدیدی که Auto Sync ایجاد کرده** و توسط اعتبارسنجی اصلی تأیید شده‌اند، فقط با آدرس `public_noindex` به رجیستری افزونهٔ STPPI وصل می‌شوند. همهٔ طراحی و جزئیات از خود STPPI می‌آید. آدرس‌ها و وضعیت برنامه‌های قدیمی حفظ می‌شوند.
- برنامه‌های دارای `needs_review`، هتل نامشخص یا ناسازگاری اطلاعات **خودکار تأیید نمی‌شوند**. در صفحهٔ `Tools → Server Auto Sync` علت وضعیت Pending نشان داده می‌شود. بنابراین R1 و R2 ممکن است تا تأیید هتل/برنامه در فهرست قبلی ظاهر نشوند؛ R3 و R4 اگر قواعد سخت‌گیرانهٔ STPPI را بگذرانند به همان طراحی وصل می‌شوند.
- گزینهٔ `Enable new public display` برای همیشه از این افزونه حذف شده؛ دیگر نباید لمس شود. در این نسخه «ظاهر قدیمی» تنها ظاهر موجود است.
- ترتیب نمایش در طراحی اصلی همچنان تابع خود STPPI است (عموماً تاریخ سفر، سپس ردیف شیت). این نسخه قالب اصلی را برای تغییر الگوریتم ترتیب دستکاری نمی‌کند.

## نصب سریع — روی 2.4

1. در WordPress → Tools → Server Auto Sync دکمهٔ **Pause database updates** را بزنید تا وضعیت `PAUSED` شود؛ این فقط برای تعویض افزونه است.
2. WordPress → Plugins → Add New → Upload Plugin → فایل `server-turizm-sync2-original-design-2.5.zip` → `Replace current with uploaded` → فعال بودن افزونه را بررسی کنید. **پوشهٔ مقصد همان `server-turizm-sync2-live` است**، پس افزونهٔ جدید جداگانه نصب نمی‌شود.
3. وارد Tools → Server Auto Sync شوید. عنوان `2.5 — Original Design` و جملهٔ `ORIGINAL STPPI DESIGN — LOCKED` باید دیده شود. اگر آخرین Sync موفق بوده باشد، اتصال برنامه‌های آماده به رندرر اصلی نیز بررسی می‌شود.
4. صفحهٔ `https://www.serverturizm.com.tr/umre-1/` را با `Ctrl + Shift + R` باز کنید. اگر کارت‌های قبلی دیده نمی‌شوند، کش سایت و CDN را پاک کنید. **روی Restore checkpoint نزنید**؛ این اقدام محتوای دیتابیس را برمی‌گرداند و راه‌حل تغییر ظاهر نیست.
5. پس از مشاهدهٔ قالب اصلی، دوباره `Start automatic updates (save checkpoint first)` را فقط یک‌بار بزنید؛ این اقدام تغییرات واقعی دیتابیس را فعال می‌کند. اگر دسترسی به بکاپ مستقل ندارید، از خطر باقی‌ماندهٔ این مرحله آگاه باشید. نیازی به فعال‌سازی یک گزینهٔ Public Display نیست.

## مواردی که هنوز نیازمند توجه هستند

- R1 / R2: وضعیت `needs_review` است؛ منتشرشدن خودکار با طراحی STPPI بدون تأیید کامل یا هتل در انتظارِ تأییدشده مجاز نیست.
- R3 / R4: در شیت و WordPress تأیید شده‌اند، ولی قرارگرفتن در نمایش عمومی تنها وقتی اتفاق می‌افتد که اعتبارسنجی STPPI و دسترسی به هتل‌ها موفق شود.
- ترتیب سفارشی جابه‌جایی ردیف‌ها ممکن است با مرتب‌سازی پیش‌فرض تاریخ در STPPI متفاوت باشد.
- این فایل‌ها روی سرور زنده نصب نشده‌اند و آزمایش رفتارشان روی هاست/قالب فعال انجام نشده است. پیش از ادامه مطمئن شوید نمایش عمومی تغییر نکرده است.

## فنی

- Script و REST/HMAC، شناسه‌های موجود، ایمنی آرشیو و Checkpoint از 2.4 حفظ شده‌اند.
- تمام hookهای ساخت کارت مستقل و مسیرهای جایگزین Auto Sync حذف شده‌اند.
- ثبت برنامهٔ جدید در رجیستری STPPI با بررسی **Stable ID + UUID + مالکیت رکورد + تأیید اصلی STPPI** و جلوگیری از برخورد Slug انجام می‌شود.
- هیچ فایل CSS، JavaScript، shortcode یا template از افزونهٔ اصلی برنامه‌ها جایگزین نشده است.
- داخل WordPress به `Tools → Server Auto Sync → Original renderer registration` برای وضعیت‌های انتشار مراجعه کنید.

**نسخهٔ نصب‌شده روی سایت را با این فایل جایگزین کنید، نه اینکه دو افزونه Sync موازی نصب شوند.**
