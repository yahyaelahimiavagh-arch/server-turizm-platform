# Server Turizm Program Intelligence v0.3.3 — Explicit Removal Intent

This is a safety/operations patch on top of the accepted v0.3.2 private-candidate baseline.

## New controlled removal workflow

`Programı Kaldır` is now treated as an explicit operator removal intent **only through a dedicated removal manifest**.

- Active Program JSON remains partial and missing rows still have no lifecycle effect.
- Google Sheets exporter v0.2.1 can export a separate `st-tde-removal-manifest/v1` file containing only rows where `Programı Kaldır` is checked.
- WordPress adds **Program Intelligence → Removal Review**.
- Removal Review resolves every manifest row by the exact Google Sheets source identity already stored on the Program entity.
- A Program-code mismatch, duplicate/missing identity, or protected fixture blocks the whole preflight.
- Archive requires an explicit administrator confirmation.
- Archive creates the existing immutable Program + Hotel snapshot and audit events.
- No Program post/entity is deleted.
- An explicit removal manifest can archive a departed/in-progress Program because `Programı Kaldır` is a direct operator instruction, not an inferred missing-row condition.
- If an active import later reintroduces the same source entity, any stale removal intent is cleared before normal review resumes.

## Spreadsheet guard

Exporter validation now blocks an active Program when `Sayaç Hedef` and `Gidiş` resolve to different exact dates. This prevents a countdown date from silently disagreeing with the departure date.

## Preserved

- ST-TDE Program Batch schema remains `1.0.0`.
- Stable `STP-*` IDs remain immutable.
- Candidate Import remains private and idempotent.
- Missing rows in a normal partial export never archive or delete anything.
- Fixtures `STP-000036` and `STP-000037` cannot be removed through the manifest flow.
- No public renderer/SEO/sitemap behavior is added by Program Intelligence.
