# Server Turizm Program Intelligence v0.3.2 — Frontend Runtime Isolation

## Scope
This is a performance-hardening patch on top of the v0.3.1 temporal-semantics candidate.

## Evidence
The owner reproduced a clear active/deactivated difference on the public homepage: active requests included multi-second outliers (roughly 3–17 seconds), while deactivated requests returned to roughly 0.6 seconds. `/umre-1/` remained around ~1 second in the same comparison.

## Change
Because v0.3.x has no public Program renderer or public route, ordinary frontend requests now stop at the plugin bootstrap before loading STPI classes or registering private CPTs. Admin, admin-post/admin-ajax, cron and WP-CLI retain the full private runtime.

## Preserved
- 35 private candidate records and existing WordPress post/meta storage
- immutable `STP-*` IDs
- Hotel `STH-*` resolution
- staged import and idempotency
- revisions and append-only audit events
- approval/archive/restore controls
- v0.3.1 pure Temporal vs Effective State UI semantics
- no public Program URL, SEO/schema, sitemap or `/umre-1/` change
